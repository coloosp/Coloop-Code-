
# 类与对象

## 封装
意义： 
1. 将属性和行为作为一个整体表现一个事物
2. 将属性和行为加以权限控制

实例化：通过一个类创建一个对象的过程

### 访问权限
|      权限       |          控制范围          |
| :------------: | :-----------------------: |
| 公共权限public  |  类内可以访问，类外可以访问  |
| 保护权限protect | 类内可以访问，类外不可以访问 |
| 私有权限private | 类内可以访问，类外不可以访问 |

注意：保护权限和私有权限的控制范围几乎相同，但是在继承方面，保护权限的内容可以被子类继承，但是私有权限的内容不可以被子类继承

### class与struct的区别

两者的区别在于：
* struct的权限默认为公共
* class的权限默认为私有

## 对象的特性

### 构造函数与析构函数

编译器提供的构造函数和析构函数都是空实现：
* 构造函数：主要作用在于创建对象时为对象的成员属性赋值，构造函数由编译器自动调用
* 析构函数：主要作用在于对象销毁前，系统自动调用，执行一些清理工作

构造函数： `类名(){}`
1. 构造函数没有返回值，不需要写void
2. 函数名称和类名相同
3. 构造函数可以有参数，可以发生重载
4. 程序在调用对象时会自动调用构造，无需手动调用，而且只会调用一次

析构函数：`~类名(){}`
1. 析构函数没有返回值，也不需要写void
2. 函数名称与类名相同，在前面要加上~
3. 析构函数不可以有参数，因此也不存在重载
4. 程序在销毁的对象时会自动调用析构，无需手动调用，而且只会调用一次

### 构造函数分类与调用

构造函数有两种分类方式：
* 按参数分：分为有参和无参
* 按类型分：分为普通和拷贝

有三种调用方式：
1. 括号法
```
//假设存在一个Person的类
//Person中存在默认构造函数（无参），有参构造函数与拷贝构造函数
Person p1;//由默认构造函数创建对象
Person p2(10)//由有参构造函数创建对象
Person p3(p2)//由拷贝构造函数创建对象
```
**注意**：在调用默认构造函数时，不要`Person p1()`的形式，编译器会误认为在声明一个返回值为Person的函数p1

2. 显示法
```
Person p1;
Person P2=Person(10);
Person p3=Person(p1);
```
显示法的实质是将匿名对象赋值给已经创建的对象

匿名对象的特点：当前行执行结束后，系统会立刻回收匿名对象

3. 隐式转换法
```
Person p1;
Person p2=10;
Person p3=p2;
```

### 构造函数调用规则
默认情况下，编译器会提供以下三个函数：
1. 默认构造函数
2. 默认析构函数
3. 默认拷贝构造函数

构造函数的调用规则：
* 如果用户定义有参构造函数，编译器不会提供默认构造函数，但仍会提供默认拷贝构造
* 如果用户定义拷贝构造函数，编译器不会提供任何构造函数

### 深拷贝与浅拷贝

**浅拷贝**：简单的赋值拷贝操作
对于拷贝构造函数来说，编译器提供的默认拷贝构造函数属于==浅拷贝==
这会存在一个问题：重复释放堆中的内存

**深拷贝**：在堆中重新申请空间，进行拷贝操作
当用户定义拷贝构造函数时，在拷贝时就会在堆中重新申请空间，属于深拷贝

### 初始化列表

在C++中，可以使用初始化列表来对属性初始化

语法：`构造函数（）：属性1（值1），属性2（值2）{}`

例如：
```
//假设在一个Person类中
Person(int a,int b,int c):person_a(a),person_b(b),person_c(c){}
```

### 类对象作为类成员

C++类中的成员可以作为另一个类的对象，称这个成员为对象成员
```
class A{
    
}
class B{
    A a；
}
```

* 对于构造顺序是：先调用对象成员的构造，再调用本类的构造
* 对于析构的顺序则相反：先调用本类的析构，再调用对象成员的析构

### 静态成员

静态成员就是在成员变量或成员函数前加上关键词static, 称为静态成员

静态成员分为：
* 静态成员变量：
    * 所有对象共享同一份数据
    * 在编译阶段就分配了内存
    * 类内声明，类外初始化
 * 静态成员函数：
      * 所有对象共享一份函数
      * 静态成员函数只能访问静态成员变量

 **注意**：静态成员也有访问权限，如果是保护权限或者私有权限，则不能在类外访问
 ```
 class Person{
    static int a;
    static void func(){
        
    }
 }
 ```
 
静态成员的调用：
1. 通过对象调用  
```
Person p;
p.a=100;
p.func();
```
2. 通过类名调用  
```
int Person:: a;
Person ::func();
```

### 成员变量和成员函数分开存储

在C++中，类内的成员变量和成员函数==分开存储==

**并且只有非静态成员变量才属于类的对象上**（只有非静态成员变量会在对象的内存中）

### this指针概念

C++会提供特殊的对象指针，**this指针**，this指针会指向被调用的成员函数所属对象

* this指针会是隐含在每一个非静态成员函数的指针
* this指针不需要定义，可以直接使用

this指针的用途：
1. 当形参和成员变量同名时，可以使用this指针区分
2. 在类的非静态成员函数中返回对象本身，可以使用return *this
```
class Person{
    int age;
    int name;
    Person (int age,int name){
        this->age=age;
        this->name=name;
    }
    Person& func(){
        return *this
    };
    Person p1(10,alice);
    Person p2=p1.func();
    //当我们创建p1对象时，实际上构造函数会将我们输入的形参赋值给p1的成员变量（this指向的age与name）
    //因为this是指向对象的指针，所以对this解引用就会得到该对象，不过在类的返回函数类型应该为引用形式，才会返回对象本体，否则返回的是对象的拷贝
}

```
### const修饰成员函数

常函数：
* 成员函数后加const后，称为常函数
* 常函数不可以修改成员属性
* 成员属性声明时加上关键词mutable后，在常函数中依然可以修改

常对象：
* 声明对象前加上const，称为常对象
* 常对象只能调用常函数

```
class Person{  
    void show()const
    {
        age=18;//不允许，常函数不能修改成员属性
        name=cirno;//允许，该成员属性有mutable修饰
    }
int age;
mutable int name;

};
const person p;
p.age=17;//不允许，常对象不能修改自己的成员变量
p.name=alice//允许，同理
```
  


**解释**：因为this指针的本质是指针常量，指针常量不允许修改指向，当成员函数加上const修饰后，指针指向的值同样不允许修改

## 友元
 友元：让一个函数或者类访问另一个类的私有成元
### 全局函数作为友元
语法：
```
void func(){
    //假设里面在调用类中的私有成员
}//全局函数
class A{
    friend void func();//将全局函数放在类的最上面
}；
```

### 类做友元

语法：同理，只需要将需要当作友元的类，加上friend放在需要访问的类的上面即可

### 成员函数做友元

语法：在需要访问的类下面放入
`friend 类名:: 成员函数名();`

## 继承
### 继承的语法
  `class A:继承方式 B`
  * A类成为子类 或者派生类
  * B类成为父类 或者基类
 子类中包含两种成员：
 * 从父类继承的，表现共性
 * 子类自己增加的，表现个性
 
### 继承方式
**继承方式**有三种：
* 公共继承
* 保护继承
* 私有继承
![继承方式](vx_images/361066473315307.png)
 无论是哪一种继承方式，决定的都是子类中成员的访问权限，子类只能继承父类中的公共权限和保护权限的成员。
 
### 继承中的对象模型
* 父类中所有非静态成员函数都会被子类继承
* 虽然私有权限的成员无法访问，但实际上也是被子类继承了（也会被子类所存储）

### 子类父类的构造析构顺序

顺序：父类构造函数->子类构造函数->子类析构函数->父类析构函数

### 子类与父类同名成员的处理

当子类出现与父类有相同成员的情况时有以下规则：
* 当子类存在与父类同名的成员函数时，子类会把父类成员函数隐藏，加上作用域可以访问到父类的成员函数
* 子类对象可以直接访问到子类的成员
* 子类对象需要加上父类作用域才能访问到父类对象
* 静态成员的规则与上面一致

### 多重继承与菱形继承问题

  
C++里面允许一个子类的多重继承，一个子类可以继承多个基类，并获得它们里面所有的成员（除了私有权限成员）

这会出现**菱形继承问题**：菱形继承问题（Diamond Problem）是指在面向对象编程中，当一个类通过多个继承路径继承同一个基类时，导致对基类成员的多重继承，从而引发的二义性问题。

这可以通过表明作用域来避免二义性问题，但是仍然会有冗余的数据被继承下来

**解决方案**：在C++中，可以通过虚继承（Virtual Inheritance）来解决菱形继承问题。虚继承确保只有一个基类子对象被继承，从而避免了多重继承带来的二义性。
```
class A {
public:
    void test() {
        std::cout << "A" << std::endl;
    }
};

class B : virtual public A {
    // B 虚继承自 A
};

class C : virtual public A {
    // C 虚继承自 A
};

class D : public B, public C {
    // D 继承自 B 和 C，它们都虚继承自 A
};

int main() {
    D d;
    d.test();  // 调用 A 的 test 方法
    return 0;
}
```
通过使用虚继承，类D只继承了一个A类的子对象，从而避免了菱形继承问题。

## 多态
### 多态的概念
**多态**分为两类：
* 静态多态：函数重载和运算符重载属于静态多态，复用函数名
* 动态多态：派生类和虚函数实现运行时多态

静态多态和动态多态的**区别**：
* 静态多态的地址早绑定——编译阶段确定函数地址，编译器在编译时根据静态类型（即变量的声明类型）来决定调用哪个函数。
* 动态多态的地址晚绑定——运行阶段确定函数地址，编译器在编译时只检查函数的调用是否合法，具体的函数实现是在运行时根据对象的实际类型来决定的。

### 虚函数与多态
案例：
```
class Animal {
public:
    virtual void makeSound() {
        std::cout << "Animal makes a sound" << std::endl;
    }
    virtual void eat() {
        std::cout << "Animal eats" << std::endl;
    }
};

class Dog : public Animal {
public:
    void makeSound() override {
        std::cout << "Dog barks" << std::endl;
    }
    void eat() override {
        std::cout << "Dog eats" << std::endl;
    }
    void bark() {
        std::cout << "Dog barks loudly" << std::endl;
    }
};

int main() {
    Animal* animal = new Dog();
    animal->makeSound();  // 输出 "Dog barks"
    animal->eat();        // 输出 "Dog eats"
    // animal->bark();  // 错误，Animal 类中没有 bark 函数
    delete animal;
    return 0;
}
```
解释：
 * **父类 Animal**：
有两个虚函数：makeSound 和 eat

 * **子类 Dog**：
重写了 makeSound 和 eat 函数。
添加了一个新的非虚函数 bark。

* **多态应用**： 
 通过 Animal* 指针调用 makeSound 和 eat，分别调用的是 Dog 类的实现。
不能通过 Animal* 调用 bark，因为 Animal 类中没有这个函数。

虚函数指针与虚函数表：
* **虚函数表（vtable**）：每个包含虚函数的类都有一个虚函数表，记录了该类的虚函数的具体实现。
* **虚函数指针（vptr**）：每个对象都有一个虚函数指针，指向该对象所属类的虚函数表。

总结以上：
* **虚函数的重写**：子类可以重写父类的虚函数，提供自己的实现。
* **多态调用**：通过父类指针调用虚函数时，实际调用的是子类中重写的函数。
* **vtable 和 vptr**：虚函数表和虚函数指针机制使得运行时绑定成为可能，从而实现多态。

### 纯虚函数与抽象类

在多态中，父类可能只是为了实现子类的重写与多态，此时实例化父类的虚函数毫无意义

因此可以将该函数改为**纯虚函数**

纯虚函数语法：`virtual 返回值类型 函数名 （参数列表） =0`

当类中存在纯虚函数，该类被称为==抽象类==

抽象类的特点：
* 无法实例化对象
* 子类必须重写抽象类中的函数，否则也属于抽象类

### 虚析构与纯虚析构：
 在多态的使用时，如果子类有属性开辟到堆区，那么父类指针在释放时（调用析构函数）无法调用到子类的析构函数
 
解决方法：将父类的析构函数改为虚析构函数或者纯虚析构函数

虚析构与纯虚析构的共性：
* 都可以解决父类释放子类对象的问题
* 都需要有具体的函数实现  
区别：
* 如果是纯虚析构函数，该类会属于抽象类，无法实例化对象

虚析构函数语法：
`virtual ~类名(){}`

纯虚析构函数语法：
```
vortual ~类名(){}=0;
类名::类名(){}

```
